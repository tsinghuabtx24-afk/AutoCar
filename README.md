# AutoCar

STM32F103 智能小车工程。当前包含电机、编码器、循迹和双路红外避障模块。

## 总体规划

循迹是车辆默认的导航行为，但不是不可中断的主体循环。红外避障、交通标志任务、鸣笛、入库等属于上层行为，可以临时抢占底盘控制权；处理完成或条件解除后，再返回循迹。

主循环只负责优先级仲裁，不实现传感器细节和具体任务动作。规划优先级如下：

1. 紧急停止和故障保护；
2. 红外避障；
3. 已经开始且必须连续完成的任务，如转弯、鸣笛、入库；
4. 新识别到的任务或标志；
5. 默认循迹。

各模块应提供短周期接口，如 `Module_Handle()` 或 `Module_Step()`。接口返回“本次是否占用了底盘”，主循环只允许最高优先级的一个模块最终写电机。

## 当前主循环约束

当前独立测试阶段，无障碍时要求车辆持续直线行驶，因此主循环默认调用 `Car_ForwardRun()`。接入循迹后，把该默认动作替换为 `LineTracker_Step()` 即可形成“循迹默认运行、避障优先抢占”的结构。


本工程保留了原有的运动测试、编码器诊断、红外诊断和循迹调试代码。调试代码可以按注释启用，不因集成功能而删除。

## 模块职责

### `car`

负责底盘运动：直行、后退、原地旋转、按编码器距离或角度动作等。不判断动作何时执行，也不读取红外或循迹传感器。

### `encoder`

负责编码器计数、里程、转速和旋转角估算。当前由 SysTick 周期采样，运动模块通过接口读取。

### `line_tracker`

负责默认循迹行为。正式集成应调用 `LineTracker_Step()`，它只执行一次读取和一次控制决策，能够被上层抢占。

`LineTracker_Run()` 是独立调试入口，内部有无限循环。集成避障或任务后不要在主循环调用它，否则上层没有机会再次仲裁。

### `ir_avoid`

红外避障是一个完整的“传感器 + 告警 + 避障动作”模块,负责：

- 左右红外发射使能和 ADC 采样；
- 阈值、迟滞和左右障碍状态判断；
- 识别到障碍并即将执行避障动作时开启蜂鸣和对应 RGB 告警；
- 告警只覆盖后退、旋转等本次避障动作，动作完成后立即关闭；
- 左侧障碍：向右原地旋转 30°；
- 右侧障碍：向左原地旋转 30°；
- 双侧障碍：先后退约 50 mm，再随机选择左或右，必须原地旋转 30°；下一轮重新检测；
- 返回是否抢占底盘控制权。

`IrAvoid_Update()` 只更新传感器状态和诊断信息；`IrAvoid_Handle()` 执行完整避障仲裁。主循环应调用后者。

红外阈值和采样参数在 `Core/Inc/ir_avoid.h`；避障动作参数在 `Core/Src/ir_avoid.c`，都需要根据实车和电池电压标定。

## 任务规划

以后新增任务时，建议增加独立任务管理模块。识别模块只发布事件，任务模块保存状态、判断优先级并驱动动作，不要把所有条件继续堆到 `main.c`。

| 事件 | 处理方式 | 完成后 |
| --- | --- | --- |
| 打开开关 | 进入运行状态 | 正常循迹 |
| 识别限速标志 | 更新巡线速度上限 | 按限速持续循迹 |
| 识别解除限速 | 恢复默认速度上限 | 正常循迹 |
| 识别左/右转 | 创建转弯任务并优先执行 | 返回循迹 |
| 识别鸣笛 | 停车，鸣笛两声 | 返回循迹 |
| 识别 1/2 号库 | 执行对应入库动作，停留 2 秒 | 按赛题定义出库或返回循迹 |
| 红外障碍 | 立即抢占导航或普通任务 | 障碍解除后重新仲裁 |

限速属于持续配置，不应设计成阻塞任务。转弯、鸣笛、入库属于有开始、有进行中状态和完成条件的任务。建议任务至少包含 `IDLE`、`RUNNING`、`DONE`、`FAILED` 状态，并具有开始时间、超时和必要参数。

## 术语说明

“有限状态任务”不是额外的硬件模块，而是一种写任务的方法：任务用少量明确状态表示当前阶段，每次循环只推进一步，并且有明确的完成、失败和超时出口。例如鸣笛任务可以有 `IDLE`（未执行）、`STOPPING`（停车）、`BEEPING`（鸣笛中）、`DONE`（完成）和 `FAILED`（失败）几个状态；完成后再把控制权交回循迹。

这样做的目的，是让转弯、鸣笛、入库等动作能够被调度、暂停或恢复，而不是在 `main.c` 里写一长段阻塞代码。当前避障已经具备“检测状态”和“动作处理”的基本分层，但 `car` 的角度/距离动作仍是阻塞式，后续应逐步改为真正的非阻塞状态机。

## 编程规则





- 正式集成模块不得使用无法退出的 `while (1)`；无限循环只允许存在于独立调试入口。
- 传感器识别与动作执行分层：识别产生状态或事件，任务模块决定生命周期和优先级，`car` 执行底盘动作。
- 同一时刻只允许一个模块最终控制电机；高优先级模块获得控制权后，低优先级模块必须跳过。
- 长动作逐步改为非阻塞状态机。当前 `Car_BackwardDistance()` 和 `Car_Rotate*Angle()` 是阻塞式动作，动作期间编码器仍由 SysTick 采样，但其他事件要等动作结束后才能仲裁。
- 每个动作必须有超时或失败出口，故障时制动停车。
- 参数使用带单位的宏名，例如 `_MS`、`_MM`、`_DEG10`，避免裸数散落在主循环。
- 不删除已有调试代码；调试入口和正式集成入口并存。

## 当前测试流程

1. 上电后初始化电机、编码器和红外模块。
2. 无障碍时固定速度直线行驶。
3. 左侧障碍时开启蜂鸣、左侧 RGB 告警，并向右旋转 30°；动作完成后关闭告警。
4. 右侧障碍时开启蜂鸣、右侧 RGB 告警，并向左旋转 30°；动作完成后关闭告警。
5. 双侧障碍时开启告警，先后退约 50 mm，然后随机选择左或右并旋转 30°；旋转完成后关闭告警。
6. 下一轮重新采样：若障碍仍存在，就把它视为一次新的避障事件，重新执行对应动作；若解除则恢复直行。
